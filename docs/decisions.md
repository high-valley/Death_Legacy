# 判断記録（ADR）

- **ADR-001 Godot 4.7 + GDScript、Compatibility レンダラー、Web はスレッドなし書き出し** — 姉妹作と同じ。GitHub Pages で動かすため。
- **ADR-002 バランス値は1つの JSON（data/balance.json）** — 等級・レア度・供物などが相互に参照するため1ファイルにまとめ、`DataLoader` で整合性を検証。
- **ADR-003 亡霊の等級は「ラン長に対する生存割合」で決める** — 仕様書の30分版の5分刻みを比例圧縮。10分ランでも3分短縮モードでも同じ基準で使える。
- **ADR-004 出撃時に予約、終了時に消費（冪等）** — 仕様 §4.1。異常終了しても複製・消失しない。放棄はリタイア扱い。
- **ADR-005 セーブは一時ファイル→検証→.bak→置換** — 書き込み中の電源断・破損に備える。Web版はブラウザ内（IndexedDB）なので端末ごとに別データ。
- **ADR-006 カードのレア度は5段階（N/R/SR/UR/LR）** — オーナー指定。レア度は「上がるLv・武器ダメージ加算・パッシブ効果倍率」で表現し、LRは所持武器の進化。
- **ADR-007 供物の割り振りはいつでも戻せる** — 好きなビルドに合わせて毎回試せるように。強くなりすぎないよう祭壇は最大10段階、縁は1枚最大4、封印は最大3枚。
- **ADR-008 封印は「新しく取る候補」だけを止める** — 形見などで既に持っているカードの強化まで止めると詰む場面があるため。
- **ADR-009 形見は使い切り・棚は5つまで** — 毎回同じ形見を使い続ける強化インフレを避ける。生還でも形見が残る＝「生還すると亡霊が残らず損」問題の緩和。
- **ADR-010 GDScript の実行時エラーはCIで失敗扱い** — テスト関数内の実行時エラーはテストを止めないため、ログの `SCRIPT ERROR` を検出して落とす。

## ADR 011: スマホ（Web版）の負荷対策
- 背景: iPhone Air で「重すぎて遊べない」。計測すると、敵300体が主人公に群がると1ティックの処理が数倍に膨らみ、
  1フレームに最大8回の追いつき処理が走って悪循環（敵300体・CPU 1/4 で 7.5FPS）。加えて高DPI（3倍）で描くピクセル数が多い。
- 決定:
  1. 敵の押し合いを「細かいグリッド＋各組1回＋型付き」に変更（ネイティブで混雑時 5.6ms → 2.1ms/ティック）。
  2. Web版は `Engine.max_physics_steps_per_frame = 3`。端末が遅い時は悪循環でなく「処理落ち（ゆっくり）」になる。
  3. 敵・敵弾・撃破エフェクトは共通の円テクスチャで描く（`draw_circle` より軽く、まとめて描画される）。HUDの再描画は20Hz。
  4. Web版のピクセル密度は最大2倍（`export_presets.cfg` の head_include で devicePixelRatio を上限2に）。URL に `?lowres` で1倍。
- 計測: Web版を URL `?bench` で開くと敵300体の負荷試験が自動で走り、5秒ごとに FPS を画面とコンソールに出す。
  ネイティブの計測は `godot --headless --path . -s res://tools/bench_sim.gd`。
- CI: 描画・UIのスクリプトは単体テストから読まれないので、実際に3秒起動して SCRIPT ERROR を検出する手順を追加。

## ADR 012: Godot から TypeScript（ブラウザ向け技術）へ移行
- 背景: Godot 4.7 の Web版は、ADR 011 の対策後も iPhone Air のブラウザで「もっさり」して遊べなかった。
  一方、同じ仕様の単一HTML試作（Canvas 2D）は同じ iPhone で滑らか。原因はゲームの中身ではなく、Godot の Web版（WASM＋WebGL）と iPhone の相性。
  GitHub Pages でスマホ確認する流れはオーナーの必須要件なので、オーナーと相談のうえ移行した（選択肢 C）。
- 決定:
  - TypeScript＋Canvas 2D、メニューは HTML。外部ライブラリなし。書き出しは esbuild、テストは Node 標準のテスト機能。
  - 設計（戦闘ロジックとセーブの分離・events・用途別乱数・状態機械・冪等な settle・予約→消費）とテストは Godot 版から移植。
  - 日本語は端末の書体（iPhone=ヒラギノ、Windows=游ゴシック/メイリオ）を使い、フォントの同梱・サブセットは不要にした。
  - Godot 版は `godot-legacy` ブランチに残す。
- Steam 版: 遊びが固まったら、同じ `dist/` を Electron で包んで Windows 版を作る（Vampire Survivors も初期はこの方式）。
  Steamworks は Electron 用の連携（steamworks.js など）を `src/platform.ts` の `steamAvailable()` から使い、Web版では読み込まない。
  セーブは `KV` をファイル保存に差し替える。
- 計測（同じ環境・敵300体の最悪ケース）: 戦闘ロジック 0.2〜0.3 ms/ティック（Godot 版は約2 ms）。書き出しは約75KB（Godot 版は数十MB）。

## ADR 013: 家系（フェーズ2）の作り
- 家系は `data/balance.json` の `lineages` に置き、効果は `mods`（倍率の足し引き）と専用カード1枚だけで表す。コードに家系名の分岐を増やさない。
- 専用カードはパッシブ枠を使わない（家系を選んだ得が枠争いで消えないように）。確率判定は新しい乱数ストリーム `lineage` を使う。
- 解放判定は `MetaService.settle` の中（冪等なので二重解放しない）。進み具合は `progress.companion_runs` / `best_weapon_level` に保存。
- 古いセーブは `migrate()` で `lineages: ["nameless"]` を補う。

## ADR 014: 画面の見た目
- 墓所の石・蝋燭・魂の3色（`--candle` 強調 / `--soul` 亡霊 / `--blood` 危険）に絞り、見出しは明朝、本文と数字はゴシック・等幅。
- 出撃画面は「左で選ぶ・右の位牌パネルで確認して出撃」の2段組。スマホ横向き（高さ520px以下）では全画面パネル＋左だけスクロール。
- Canvas の色は `src/view/theme.ts` を CSS の変数と同じ値にしておく。

## ADR 015: 亡霊の3択と穢れ・怨霊（フェーズ3）
- 3択は保管庫の亡霊を選んだ時に出す。連れていく・喰らうは出撃時に確定（`reserve` の `ghostMode`）、弔うはその場で確定（`MetaService.mourn`）。
- 喰らう: 同行はせず、等級の倍率に比例して与ダメージ・最大HPが上がる。単独の経験値ボーナスはつかない。ラン後（`settle`）に亡霊は `wraith` になる。
- 穢れは「祓っていない怨霊の数」から毎回計算する（別の数値として保存しない＝ずれない）。敵のHP +6%/穢れ。
- 怨霊は一番古いものから1体だけ、ランの45%の時点で現れる。どの怨霊が出るかは出撃時に `active_run.wraith_id` へ保存し、再開しても変わらない。倒したかはチェックポイントの `wraith_dead`。
- 戦闘を作る材料は `MetaService.runOpts(active_run)` の1か所に集めた（出撃・再開・テストで共通）。

## ADR 016: 祭壇の樹（祭壇と書庫の統合）
- 「供物を割り振る・いつでも戻せる」は残しつつ、見た目と選び方を樹（節を親から順に開く）にした。オーナーの希望（2026-10）。
- 節は `data/balance.json` の `tree`（x, y で位置、parents で枝）。効果は足し合わせ。縁・封印は「開いた枠の中で無料で付け外し」。
- 「樹をほどく」で全額戻る。セーブは schema_version 2。v1 からの移行では払っていた供物をすべて戻す（試作段階なので節の自動変換はしない）。

## ADR 017: 武器の段階（グレード）と槍・斧
- オーナーの希望（2026-10）: 「剣の種類が増えていく感じ（短剣 → ロングソード → グレートソード → デュランダル）」。
- 武器ごとに4段階を `data/balance.json` の `weapons.<id>.grades` に置く。Lv1・3・5 で持ち替え、最後の段階はレジェンドレアの進化（Lv3以上の武器だけ、`evolve_min_level`）。
- 段階は「名前と形（範囲・本数・貫通・方向など）」を変え、Lvは同じ段階の中での伸び。数値は武器の基本値への倍率なのでデータだけで調整できる。
- 槍（直線を貫く突き）と斧（戻ってくる投げ斧・行きと帰りで当たる）を追加。亡霊も同じ武器コードで攻撃する。
- 段階の求め方は `src/data/weapons.ts`（戦闘・セーブ・画面で共通）。

## ADR 018: 画面の作り直し（画面イメージに寄せる）と絵の差し替え口
- オーナーの画面イメージ（暗いゴシック・金の飾り枠）に合わせ、タイトル / 出撃準備（記録庫・出撃・軌跡の3列）/ 戦闘HUD（ミニマップ・武器スロット・亡霊の札・ダメージ数字）/ レベルアップ / リザルト（YOU DIED）を作り直した。
- 描き込まれた絵（肖像・背景）はコードでは作らない。`art/` に決まった名前で置くとビルド時に一覧を埋め込み（`__ART__`）、`src/view/art.ts` が使う。無い絵は等級色の光と紋章の仮表示。一覧は `docs/art_assets.md`。
- アイコンは `src/view/icons.ts` の SVG パスを DOM とキャンバスで共有。英字は Google Fonts の Cinzel（読めない時は明朝で代わりに表示）。
- ダメージ数字はシミュレーションが `dmg` イベントを出す（描画側が頼んだ時だけ、1ティック12個まで）。

## ADR 019: 魔導書を炎・氷・雷の3冊に分ける
- オーナーの希望（2026-10）: 魔法は「魔導書」で統一し、炎・氷・雷を別の武器として考えたい。
- 炎の魔導書（id `fire`、従来の炎の範囲攻撃。家系「火守」の武器）/ 氷の魔導書（`ice`、刃が当たった敵を遅くし、Lv5以上は一瞬凍らせる。冥王・怨霊は凍らない）/ 雷の魔導書（`thunder`、近い敵から敵へ飛び移る。1回ごとに15%弱まる）。
- id `fire` は古いセーブ・亡霊・家系の条件のために残す。各冊4段階で、最後は伝説の禁書（レメゲトン / ニブルヘイムの書 / ケラウノスの書）。

## ADR 020: 絵は「主人公を選ぶ」ために使い、亡霊は紋で表す
- オーナーの希望（2026-10）: 亡霊は人の絵でなくてよい。主人公を絵の人物で選ぶ（絵＝武器種の選択）。
- 出撃準備の「主人公」で7人（剣・弓・槍・斧・炎/氷/雷の魔導書）から選ぶと、その武器で出撃。戦闘HUDの左上にその顔。
- 亡霊（記録庫・同行の札・リザルト）は等級色の霊光＋生前の武器の紋。
- 選ぶ時の武器名は「剣」「弓」など大分類。レベルアップで段階名に持ち替える（剣: 短剣 → ロングソード → グレートソード → デュランダル、炎: ファイア → フレイム → インフェルノ → エクスプロージョン、氷: アイス → フロスト → ブリザード → アブソリュートゼロ、雷: サンダー → ライトニング → サンダーボルト → ジャッジメント）。

## ADR 021: 亡霊は消費しない・最大2体・主人公は武器1種・ビルドを濃く（オーナー判断 2026-10）
- **確定ルールの変更**（オーナーが明示的に了承）: 連れていった亡霊はランの後に保管庫へ戻る（減らない）。保管は10体まで。失うのは喰らう（怨霊化）・弔う・満杯時の入れ替えだけ。
- **亡霊になる条件**: ランの30%以上を生き延び、未練の欠片を2つ以上持って死ぬ（`ghost_birth`）。欠片は墓暴き1・怨霊2。余った欠片1つにつき等級が1段上がる。
- **同行は最大2体**（`ghost_slots`、2体目は祭壇の樹「双魂の契り」）。1体ずつ「連れていく / 喰らう」を選べる。セーブ v3 で `active_run.ghosts[]`。
- **主人公は武器1種**（`sub_weapon_slots: 0`）。武器の形見は主人公の武器のLvになる。
- **ビルド**: タグ（炎・氷・雷・斬・突・射・霊）とセット効果（2/4/6）。点数は主人公の武器2・亡霊の武器1＋霊1・タグ付きパッシブ1Lvにつき1。Lv3 で武器の道を2つから選ぶ（Lv5 も同じ道の先、進化は共通）。刻印カード（`sigils`、祭壇の樹の書架で種類が増える）、呪いカード（`curses`、禁忌の頁で解放）。乱数は新しい `build` ストリーム。
- 簡易ボットは「武器 → ビルドに合うタグのパッシブ → 攻撃系」の順で選ぶようにした（以前は先頭を取るだけで、人の遊び方とかけ離れていた）。この条件で各武器 7〜12/12 クリア（3分モード・単独）。難度は人の感想で調整する（`player.weapon_mult`、`spawn.hp_growth` など）。

## ADR 022: 10分モードの難度を別立て・戦闘キャラを絵（スプライト）に（2026-10）
- 10分モードは3分モードより易しかった（時間が長い分だけ主人公が育ちすぎる）。敵の硬さ・攻撃力の伸びを `full_hp_growth` / `full_dmg_growth` で別に持ち、`full_curve`（2＝進み具合の2乗）で序盤はゆるく終盤に急に強くする。直線だと序盤から詰んだため。冥王・怨霊の攻撃は固定。
- 戦闘中のキャラは `art/sprite_*` の透過絵があれば絵で描く（無ければ図形のまま）。3Dモデルは使わない: Canvas 2D の描画で十分、スマホの負荷も軽い。動き（向きの反転・影・揺れ）はコードで付ける。
- 主人公の動き: 1枚絵を足元を軸に弾ませ・傾け・踏み込ませる（`HeroAnim`、描画側だけの状態）。剣の斬撃は先端が太い三日月形で、振る回りを交互にする。コマ絵（`_walk_N` / `_attack_N`）があれば差し替える。剣だけを切り抜いて回す案は、絵の中で剣が脚に重なっていて切り抜けないため見送り。

## ADR 023: 拠点の施設「堂守の亡霊」（オーナー判断 2026-10-21）
- 役割分担（提案者 → 仕様確認者 → オーナーが選ぶ）で決めた。経緯と却下案は `docs/proposals/facilities.md`。
- 納骨堂に「霊廟」タブ。施設を供物で建て（**戻せない**。樹をほどいても戻らない）、保管中の亡霊を住まわせる。**住んでいる亡霊は連れていけない・喰らえない**（亡霊は減らない＝[確定]の核は守る）。保管10体には数える。
- 施設（`data/balance.json` の `facilities`）: 鎮魂堂（等級×生き延びた割合で供物、リタイアは0）/ 武具の間（住む亡霊の武器タグ +1点）/ 供養塔（弔った回数5回ごとに永続の小さな力）。
- 亡霊の状態は増やさず `stationed_at` を足した。弔う・満杯の入れ替えで外れる。出撃中は建てる・住まわせる・外すができない。
- 効果は出撃確定時に `active_run.facility` へ写し、`runOpts()` から戦闘へ渡す（再開しても変わらない）。鎮魂堂の供物は `settle` で1回だけ。
- セーブ v4: `buildings`、`progress.mourned_count`（古いセーブは弔った記録＝consumed_at 付きの released から数える）。
- 注意: 施設の費用は `balance.json` の今の値から計算する（祭壇の樹と同じ）。建てた後に費用を変えると使える供物がずれるので、費用を変える時は注意。古いセーブの「弔った回数」は残っている記録（最大30件）からしか数えられない。

## ADR 024: 武器のランクとレベルを分ける・カードを増やす・難度をランの後半で上げる（オーナー判断 2026-10-21）
- **ランク**（武器そのもの・攻撃の形）と**レベル**（ダメージだけ）を分けた。レベルは武器カードで最大 Lv20（`weapon_max_level`）、1Lvで `per_level`（約 +12%）。武器が `rank_levels`（Lv2・4・8）に届くと、次のレベルアップで「ランクアップ」の札が必ず出る（最初は道 a / b の2枚、最後は進化）。LR はもう進化ではなく、レベルが大きく上がるカード。
  - 最初は Lv5・10・15 を考えたが、3分モードでは武器が育たず中盤に押し切られた（簡易ボットで単独 0〜3/28）。旧版は 50秒ほどで最終段階だったので、Lv2・4・8 にした。
  - レベルで攻撃間隔・射程・範囲が伸びる処理はやめた（ダメージだけ）。グレードの lv（1・3・5）はランクの並びの印として残し、`gradeAt(W, rank, evo, branch)` で引く。
- パッシブは最大 Lv8・1段の効果を約2/3（`per` を戦闘でもそのまま使う。以前は汎用6種がコードに直書きだった）。タグの点数は1Lvで0.5点。新パッシブ10種（会心・被ダメ軽減〔下限4割〕・回復・特効・各タグの2種目）。攻撃間隔の短縮は合計 `cd_cut_max`（50%）まで。会心は主人公の攻撃だけ・新しい乱数ストリーム `crit`。
- 呪い +7種（捨て身・鈍重の殻・貪る口・群れ呼び・焦燥・血の渇き〔30%で止まる〕・早熟〔パッシブ3個以下の時だけ〕）。亡霊を強くする呪いは入れない（オーナー判断）。刻印 +2（不屈〔snapshot に使った印〕・狩人の誉れ）。
- 一人の時、主人公の武器と関係ない属性のタグ付きパッシブは候補に出さない（亡霊・武具の間で入ったタグは出る）。
- 難度: 「1回のランの中で」後半ほど厳しく（オーナー判断）。3分モードも `spawn.curve`（2＝進み具合の2乗）で、序盤はほぼ一撃・後半は硬い。`hp_growth` 6.5、`dmg_growth` 1.3、`per_progress` 7、`solo_xp_bonus` 0.3（単独だけ育ちが速い）。武器カードの出やすさ `weapon_card_weight` 4。
  - 簡易ボット（6 seed×7武器）: 3分 単独 16/42・亡霊2体 28/42、10分（2 seed）単独 6/14・亡霊2体 5/14。旧: 3分 単独 20/28・亡霊2体 28/28。
- 説明書（タイトル・納骨堂・一時停止から）を追加。数値は balance.json から読む。
- セーブ v5: 亡霊の `weapon_rank`、古い武器Lv（1〜5）→ ランク＋新レベル（`legacyWeapon`）、パッシブLv ×1.6、中断ランの ppow ×1.5。

## ADR 025: 亡霊の作り直し・家系を一旦なし・30分モードを本番に（オーナー判断 2026-10-22）
- 役割分担（提案者 → 仕様確認者 → オーナーが選ぶ → 実装 → レビュー）で決めた。**[確定]の核「生存時間が長いほど亡霊が強い」をオーナーの判断で変更**（GDD §1-2・§3・§4.2 を更新）。
- **亡霊は等級・生前の Lv・ランクを引き継がない**。どの亡霊も Lv1・最初のランクから。違いは武器の種類と**特技**（生前に一番育てたパッシブ。`ghost_traits` の小さな効果、その亡霊にだけ効く。タグ点は付けない）。等級・時間による解放率（`tiers`・`ghost_unlock`）は削除。
- **亡霊の札**: 連れている亡霊1体につき `gweapon`（亡霊の武器Lv。一度に `lv_mult` 倍上がる）が3枚に混ざる。Lv が `ghost_cards.rank_levels` に届くと `grank`（亡霊のランクアップ・道選び・進化）が必ず出る。ランクアップは主人公 → 亡霊1 → 亡霊2 の順で1回1組。`dry_limit` 回続けて亡霊の札が出なければ次は必ず1枚（乱数を使わない救済）。刻印・呪いは亡霊の札を上書きしない。育ちは中断セーブ（`gstate`）に残し、保管データには書き戻さない。
- 亡霊の強さ: 同じLv・ランクの主人公の武器の `base_mult` 倍（攻撃力・攻撃速度のパッシブは乗らない。タグ付きパッシブとセット効果は乗る）。共鳴の点は「1点＋ランク1つにつき `ghost_rank` 点」。霊6 は「亡霊の武器 Lv+3（ダメージだけ）」に。
- **亡霊の守り**（今回の調整で追加）: 連れている亡霊1体につき受けるダメージが `spawn.modes.*.ghost_guard` 減る（30分 20%・10分 5%・3分 0）。30分モードで「一人ではほぼ無理、亡霊2体なら届く」にするため。
- **クリア時も残せる**: 生還すると無条件で「英霊」として残すか選べる。死亡時も（条件を満たせば）残すか選べる。`settle` で `pending_ghost`（kind=offer）→ `decideOffer(keep)`。満杯なら入れ替え（kind=full）。世代数を先に進めて亡霊の「第N代」と形見をそろえた。
- 等級を使っていた所は固定値に: 喰らう力（`rites.devour`）・弔う供物（`rites.mourn.offerings`）・鎮魂堂（`effect.offer`）・怨霊のHP（`hp_bonus`）。亡霊の色は武器のタグの色。
- **家系は一旦なし**（`lineages_enabled: false`。データと仕組みは残し、テストは家系のファイルだけ有効にして確認）。
- **30分モード（`long`）を本番に**（出撃の既定）。3分・10分は残す。敵の伸び・精鋭の回数・冥王/怨霊のHP・単独の経験値ボーナス・亡霊の守りを `spawn.modes` でモードごとに持つ。
- 簡易ボット（主人公の武器のタグを優先・亡霊の札も取る、祭壇の樹なし）: 30分 一人 2/14・亡霊2体 7/14、10分 一人 4/14・亡霊2体 12/14、3分 一人 15/28・亡霊2体 19/28。
- セーブ v6: `pending_ghost_kind`、亡霊の名前の等級名を「亡霊」に、古い入れ替え待ちは full。
- 補足: v5 の中断ラン（出撃中のセーブ）を v6 で再開すると、連れている亡霊は Lv1 から（育ちの記録が無いため）。満杯の入れ替え画面にも「やっぱり残さない」を置いた。

## ADR 026: 「ホーム」・世代表示と形見をなくす（オーナー判断 2026-10-22）
- 拠点画面の名前を「納骨堂」から「ホーム」に。
- 「第N代」の表示をなくした。亡霊は「弓の亡霊」、同じ名前は「・二」「・三」（`MetaService.ghostName`）。古いセーブの名前からも外す。内部の `progress.generation` はラン数として残す（軌跡の #番号）。
- **形見をなくした**（世代交代を前提にした仕組みのため）。棚・出撃時の選択・ラン後の候補・効果をすべて削除。セーブ v7 で `heirlooms`・`pending_heirloom`・`heir_seq` を捨てる。家系「無名」の「形見 +1Lv」も削除。
