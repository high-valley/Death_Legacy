# DEATH LEGACY — ゲーム開発仕様書

- 文書版数: 1.0（企画・MVP設計用）
- 更新日: 2026-10-16
- 対象: Steam / Windows PC（将来はWeb・スマートフォンへの展開も検討）
- 想定エンジン: Godot 4.x / GDScript（提案。アーキテクチャ設計段階で再評価可）
- ジャンル: 2D見下ろし型サバイバー・ローグライト
- 画面: 横長、マウス・キーボード優先
- 目的: Claude Codeによるアーキテクチャ設計・MVP実装の入力仕様

> 本書で **[確定]** は会話で合意したコア仕様、**[提案]** は開発開始時の仮決定、**[後回し]** はMVP外を意味する。

## 1. エレベーターピッチ

「今日の自分が、明日の仲間になる。」

主人公を直接操作し、敵の大群を倒してレベルアップしながら生存するヴァンサバ型アクション。死亡した主人公は、そのランの生存時間・ビルド・戦績を反映した**亡霊**として記録される。次のランの出撃前に、過去の亡霊を**連れていく／連れていかない**を自由に選べる。**一度連れていった亡霊はそのラン終了時に消費され、二度と使えない**。強い亡霊を作るために長く生き延び、貴重な一回限りの援軍をどのランに投入するかが戦略の核。

## 2. デザイン原則

1. **主人公が主役 [確定]**: 亡霊なしでも成立する移動・自動攻撃・レベルアップ・ビルド構築が中心。亡霊は補助戦力であり、主人公の操作・育成を代替しない。
2. **死亡を資産に変える [確定]**: ラン失敗でも亡霊が残る。生存時間が長いほど次に残す亡霊が原則強い。
3. **集めて残る亡霊 [確定・2026-10 オーナー判断で変更]**: ~~出撃時に指定した亡霊はそのランの終了後に消費~~ → 連れていった亡霊はランが終われば保管庫に戻る（減らない）。保管は最大10体。失うのは「喰らう」「弔う」「満杯時の入れ替え」だけ。その代わり、亡霊になる条件を険しくした（ランの3割以上を生き延び、未練の欠片を規定数持って死ぬ）。同時に連れていけるのは最大2体（2体目は祭壇の樹で解放）。主人公の武器は1種類で、武器の幅は亡霊が担う。
4. **任意の同行 [確定]**: 亡霊を使わず単独出撃も可能。
5. **運ではなく判断を増やす [提案]**: 戦闘ビルド、亡霊育成目的、単独／同行の選択で戦略が変わる。
6. **視認性と処理性能 [提案]**: 大量の敵を表示しても主人公・亡霊・危険攻撃が判別できる。

## 3. コアゲームループ

### ラン開始前

- 亡霊保管庫を閲覧。各亡霊の生存時間、使用武器、主要スキル、等級、固有効果を確認。
- **単独出撃**または保管済みの亡霊**1体を選択**して出撃 [提案: MVPの同行上限1体]。
- 装備やクラスの初期選択はMVPでは簡略化（初期武器を選ぶのみ）。

### ラン中

- WASD移動、敵を自動攻撃（最寄りまたは優先対象）。敵から回避しながら経験値を取得。
- レベルアップ時、ランダム候補3つから強化1つを選択。武器、パッシブ、進化を組み合わせて主人公を強化。
- 同行亡霊がいる場合は自律追従・自動攻撃。主人公の取得レベルに応じて亡霊性能の解放率が上昇 [提案]。
- 雑魚ウェーブ、精鋭、時間経過ボスを突破。
- HPが0で敗北、最終ボス撃破でクリア。

### ラン終了時

- **主人公が死亡した場合**: 生存時間の最低ラインと未練の欠片を満たしていれば、生存時間とビルドから新規亡霊を生成し、保管庫に追加 [確定・2026-10 変更]。
- **主人公が最終ボス撃破で生還した場合**: 亡霊化せずクリア記録と解放報酬を獲得 [提案]。死亡前提でクリアを不利益にしないため、クリア時に任意で「引退して亡霊化」を選べる仕組みは将来検討。
- 同行した亡霊は勝利／敗北にかかわらず保管庫へ戻る [確定・2026-10 変更]。
- 報酬・戦績・亡霊生成結果を表示、次のランへ。

## 4. 亡霊システム詳細

### 4.1 ライフサイクル [確定＋提案]

`未存在 → (主人公死亡) → 保管済み → (出撃前に選択) → 出撃中 → (ラン終了) → 成仏（使用済み）`

- 保管済みのままなら次回以降も温存できる。
- 出撃確定後のキャンセル・アプリ異常終了による不正再使用を防ぐため、選択亡霊をセーブ上では **reserved（使用予約）** にする。ラン再開時は同じ出撃を復元する。
- **消費タイミングの定義**: 通常の完走／死亡／ゲーム内リタイアでそのラン終了時に消費。アプリ強制終了は自動で消費せず同じランを再開可能 [提案]。
- 同じ亡霊を複製したり、1ランに複数連れていくことはMVPでは不可。

### 4.2 性能継承

- **生存時間 [確定]**: 亡霊の等級・基本ステータス倍率を決定。長く生きるほど原則高性能。
- **生前のビルド [確定]**: 最も成長したメイン武器1つと代表パッシブ1つを継承（MVP）。
- **生前の戦績 [提案]**: ボス撃破や特定行動で小さなボーナス。過度な複雑化を避けMVPでは1種の特性のみ。
- **死亡原因 [提案/MVP後]**: 炎死・毒死・ボス死などから固有能力を付加（実装は後回し）。

#### 生存時間と等級（本編30分用の初期バランス案）

| 生存時間 | 等級 | 攻撃補正 | 備考 |
|---|---|---:|---|
| 0:00–4:59 | 残響 | 0.5x | 早期死亡にも最低限の資産価値 |
| 5:00–9:59 | 下級霊 | 0.8x | |
| 10:00–14:59 | 戦霊 | 1.2x | |
| 15:00–19:59 | 英霊 | 1.7x | |
| 20:00–24:59 | 大英霊 | 2.3x | |
| 25:00–29:59 | 伝説の英霊 | 3.0x | |

倍率は **亡霊の基礎攻撃部分のみ** に掛け、スキル頻度、範囲、状態異常に無制限には掛けない。数値は調整可能なデータファイルから読み込む。MVPは10分ランなので閾値を比例圧縮して使用する。

### 4.3 同行時のふるまい

- 亡霊は主人公を自律追従し、射程内の敵を自動攻撃。
- 亡霊は衝突で主人公を妨害しない。敵に対してはダメージ判定を持つ。
- 亡霊の表示は半透明＋輪郭色。敵・主人公・亡霊を色とシルエットで区別。
- 亡霊の性能は主人公レベルに応じて段階的に解放される [提案]。例: 初期25%、Lv10で50%、Lv20で75%、Lv30で100%。強い亡霊でも出撃序盤を完全に代行しない。
- 亡霊の装備変更／成長選択は不可。操作負荷を避け、現在の主人公の成長に集中させる。

### 4.4 単独出撃の魅力 [提案]

- 単独出撃時は経験値獲得量 +10%（MVPはON/OFF可のパラメータ）。
- 亡霊同行時は純粋な戦力強化を得るが、消費リスクがある。
- 単独クリア実績や追加報酬は製品版で検討。単独が圧倒的有利にならないように調整。

### 4.5 亡霊の保存容量

- MVP: 最大10体 [提案]。満杯時は新しい亡霊生成を捨てない。終了画面で「保管する／既存亡霊を成仏させて入れ替える」を選択させる。
- 製品版: 30体程度への拡張を検討。

## 5. 主人公・戦闘仕様

### 5.1 基本操作

| 操作 | キー／入力 | 詳細 |
|---|---|---|
| 移動 | WASD / 矢印 | 8方向、斜め速度を正規化 |
| 攻撃 | 自動 | 所持武器のクールダウンに応じる |
| 回避 | Space | 短距離回避、無敵時間はテストで調整 |
| 一時停止 | Esc | メニュー |
| 強化選択 | マウス / キーボード | レベルアップ中はゲームを一時停止 |

### 5.2 成長

- 経験値ドロップは一定距離で主人公に吸着する。
- レベルアップごとに3候補から1つ選ぶ。重複選択で武器／能力を段階的に強化。
- MVP武器: 剣（近距離扇形）、弓（単体射撃）、炎魔法（範囲／継続ダメージ）。
- MVPパッシブ: 攻撃力、攻撃速度、移動速度、最大HP、攻撃範囲、経験値取得範囲。
- 所持上限 [提案]: メイン武器1、サブ武器2、パッシブ4。ラン内の強化内容は死亡時の亡霊生成に使う。
- レベル上昇に必要なXPはカーブ（データ駆動）で調整。

### 5.3 敵・イベント

- MVP敵: 追跡型、突進型、遠距離射撃型の3種類。
- ボス: 大型1種類。時間経過で登場し、わかりやすい予兆付き範囲攻撃を使う。
- スポーン密度は時間帯ごとに段階上昇。難度は亡霊同行の有無で固定的に変化させず、まず通常バランスを検証。
- 初期段階は毎秒の大量の敵を処理できる設計（敵100〜300体程度を目標）とし、描画方式を計測して確定する。

### 5.4 亡霊と主人公の共鳴 [製品版提案]

同属性や補完属性の組み合わせで一時的な相乗効果を発生させる。MVPは未実装（または炎×炎の1パターンのみ）。亡霊同行が強制選択にならないよう、強化幅は制限する。

## 6. 勝利・敗北・進行

- ランの終了条件を **player_death / boss_cleared / retired** として保存。
- 本編目標: 30分到達後の最終ボスを撃破。
- MVP目標: 10分到達後のボスを撃破。
- 敗北時も戦績と亡霊を生成するため、最初の1〜2周で成長実感が得られるようにする。
- 永続アップグレードは序盤は最小限（例: 初期最大HP +5%、初期装備解放）とし、亡霊継承の特徴を薄めない。

## 7. 画面一覧

1. **タイトル**: New Game / Continue / Settings / Quit。
2. **拠点・出撃準備**: 亡霊保管庫、単独出撃ボタン、亡霊1体の選択、出撃確定、ラン履歴。
3. **戦闘**: 主人公HP、経験値、レベル、経過時間、武器アイコン、同行亡霊の名称と生存時間。
4. **レベルアップ**: 3枚の強化カード、現在のビルド情報。

7. **亡霊詳細**: 等級、性能、前世の戦績、未使用／使用済み状態（履歴）。

## 8. データモデル案（エンジン非依存の概念）

### GhostRecord

```json
{
  "ghost_id": "uuid",
  "origin_run_id": "uuid",
  "created_at": "ISO-8601",
  "display_name": "第七代・炎の英霊",
  "survival_seconds": 1432,
  "tier_id": "greater_hero",
  "class_id": "fire_mage",
  "primary_weapon_id": "fire_orb",
  "passive_id": "attack_speed",
  "kills": 1876,
  "boss_kills": 2,
  "death_cause_id": "boss_fire",
  "stat_snapshot": {"attack": 50, "attack_speed": 1.4, "max_hp": 130},
  "status": "stored"
}
```

`status`: `stored`（保管）/ `reserved`（出撃中）/ `consumed`（使用済み）。能力は生成時に確定し、後のバランス更新に備えて `data_version` を保持する。

### RunRecord

```json
{
  "run_id": "uuid",
  "seed": 123456,
  "duration_seconds": 1432,
  "result": "player_death",
  "selected_ghost_id": "uuid-or-null",
  "player_build": {"weapons": [], "passives": []},
  "player_level": 31,
  "kills": 1876,
  "boss_kills": 2,
  "ended_at": "ISO-8601"
}
```

### SaveData

`schema_version`, `player_progress`, `ghost_inventory`, `run_history`, `active_run_checkpoint`, `settings` を含む。保存はゲームローカルのユーザーデータ領域に行う。原子的書き込み（一時ファイル→置換）、バックアップ1世代、スキーマバージョンのマイグレーションを設計する。

## 9. システム構成の要求（Claude Codeが具体化する項目）

- 戦闘ロジック、スポーン、レベルアップ、亡霊生成、セーブ／消費処理、UI表示を明確に分離。
- `GameSession`, `PlayerController`, `CombatSystem`, `EnemySpawner`, `ProgressionSystem`, `GhostFactory`, `GhostFollower`, `GhostInventory`, `RunSettlementService`, `SaveRepository` 等の責務分割を検討（クラス名は提案）。
- 戦闘中の亡霊は保存データのコピーから生成し、元の保管データを直接編集しない。
- 全数値（生存時間閾値、等級倍率、XP曲線、武器性能、出現テーブル）をJSONまたはResourceで外部定義。
- ラン終了処理は **二重実行されても亡霊を二重生成・二重消費しない** 冪等処理にする。
- セーブの読み込み不整合、空保管庫、保存上限、同一亡霊の重複選択に対応する。
- 敵が多い場合の描画・AI更新・当たり判定の最適化方針を設計し、フレーム計測を用意する。

## 10. MVPスコープ

### 必須

- 1マップ、主人公1人、武器3種、パッシブ6種。
- 通常敵3種、ボス1種、10分ラン。
- 移動、回避、自動攻撃、経験値取得、3択レベルアップ。
- プレイヤー死亡時に、**生存時間と武器構成を反映した亡霊を1体生成**。
- 保管庫最大10体、未使用の保管、同行有無の選択、同行1体、自動追従／攻撃。
- **同行した亡霊はラン終了時に必ず1回消費**。
- 結果画面、セーブ／ロード、同一ラン再開時の消費整合性。
- 亡霊なしでもクリア可能なバランスを目標とする。

### MVP対象外

- 複数亡霊同時同行、魂力管理、亡霊融合、世代交代、死神の襲来、複雑な死因特殊能力、オンライン要素、ランキング、課金、複数プラットフォーム同時対応。

## 11. 受け入れ条件（動作確認）

1. 新規データで亡霊0体でもゲームを開始でき、敵・レベルアップ・ボス・敗北を体験できる。
2. 5分生存して死亡した場合、5分相当の等級・武器タイプの亡霊が1体保存される。
3. 亡霊を同行させずに出撃しても、保存中の亡霊数・状態は変化しない。
4. 亡霊を同行させて死亡した場合、その亡霊は `consumed` になり、次回選べない。今回死亡した主人公から新たな亡霊は生成される。
5. 亡霊を同行させてボスを倒した場合も、その亡霊は `consumed` になる。
6. 選択中の亡霊が表示と一致し、生前の武器と生存時間に見合う性能で追従・自動攻撃する。
7. 同じランの終了処理を2回呼んでも、亡霊の生成・消費が重複しない。
8. 異常終了から復帰しても、同行亡霊の不正複製や消失が起きない（同じラン再開方式）。
9. 保管庫が10体の状態で新規亡霊を生成しても、入れ替え選択でデータを維持できる。
10. 100〜300体の敵を想定した負荷試験の結果を取得できる（目標FPSは対象PC仕様とともに確定）。

## 13. 要検証項目・意思決定

1. 生存時間を単調増加の直接倍率にすると、30分逃げ続けるビルドが最適化しないか。
2. 亡霊1体の支援効果は、主人公火力の何割程度に抑えるべきか。
3. 亡霊が出撃時点で消費予約される設計のUX。明確な警告を出す。
4. ボス撃破で生還すると亡霊が残らない仕様でクリアが損に感じられないか。
5. 死亡時の亡霊の保存と保管枠整理をどう自然に見せるか。
6. 亡霊の能力の段階解放は必要か。MVPテストで判定。

4. 亡霊の生成・予約・消費の状態遷移と中断復旧フロー。
5. Resource/JSONのデータ定義、保存フォーマットとマイグレーション方針。
6. 最初の縦切りプロトタイプのスコープ、実装タスクを依存順に分割。
7. ユニットテスト／結合テスト／プレイテストの方針。
8. 未決定事項・技術的リスクと推奨する初期値。

**絶対に維持する核:** 主人公育成が中心、死後の亡霊は生存時間で強くなる、亡霊同行は任意、一度出撃した亡霊はそのラン後に永久消費。
