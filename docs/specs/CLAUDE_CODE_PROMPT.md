同じフォルダの `DEATH_LEGACY_GDD.md` を読んでください。ゲームを開発するためのアーキテクチャを設計したいです。

## 最初に実施すること

1. 仕様内の [確定] を変更せずに、[提案] と [後回し] を区別して整理してください。
2. Windows/Steam向けのGodot 4.x + GDScriptを第一候補に、技術選定理由と代替案を示してください。
3. `docs/architecture.md`, `docs/data-model.md`, `docs/gameplay-state-machine.md`, `docs/mvp-plan.md`, `docs/test-plan.md` の5ファイルを作成してください。
4. ディレクトリ構成・シーン構成・主要クラスの責務・通信方法（signalsなど）・データ駆動設計・セーブの整合性を明記してください。
5. 特に亡霊の一回限りの利用について、予約→実行→消費、途中終了→再開、二重処理防止の仕様を詳細化してください。
6. MVPを小さな実装チケットに分け、各チケットの受け入れ条件を付けてください。
7. 不明点は `docs/open-questions.md` にまとめ、推奨案を併記してください。

まず設計文書だけを作ってください。コード実装や依存パッケージのインストールはしないでください。

## コア原則

- 主人公を自分で操作し、主人公の育成がゲームの主役。
- 主人公が死亡すると、生存時間が長いほど強い亡霊が生成される。
- 次の出撃前に亡霊を同行させるかどうか選択できる。
- 一度連れていった亡霊はその出撃終了時に消費され、再使用できない。
- MVPの亡霊同行は最大1体。
- 亡霊なしでも楽しめるゲームにする。
